## 1. オーナー決定（2026-11-15・第1283）

1. **音源と `.lys` の紐づけは、`.lys` の隣のファイルだけに置く。`.lys` には何も書かない。**
   - 隣のファイルは Orecchiante の `<名前>.orecchiante.json`（SIDECAR.md 形式 1）を広げたもの（形式 2＝人が直してよい）。
     音源は同じフォルダのファイル名（パスは持たない）。小節の時刻・人が確かめた印・拍・section のマーク・
     名前つきのループ・調律のずれ（セント）もここ。
   - 理由: 小節の時刻は音楽ではなくその録音の情報（パス 1 行だけ `.lys` に書いても数は別に要り、置き場所が 2 つになる）。
     `.lys` は人に渡す物で、音源は大きく著作物のことも多く、パスは機械ごとに違う。隣のファイルを消せば機能ごと消え、`.lys` は一字も変わらない。
   - Orecchiante を使わずに人が録音を選んだときも、Lily# が同じ形のファイルを作る（Transcribe! のように小節を人が打つ所から始める使い方も同じ道）。
   - `.lys` の名前を変えたら、拡張がリネームを拾って隣のファイルも変える（紐づけを切らない）。
2. **音源が無いとき、VS Code の UI には何も出さない。** 入口はボタンを置かない所だけ（§2）。
   隣のファイルがある `.lys` のプレビューにだけ録音の UI が現れる。
3. **小節マークはプレビューのヘッダ（ツールバー 1 行）の下に出す、畳める帯。** 役目を分ける:

   | 場所 | 役目 |
   |---|---|
   | 楽譜 | 「どの小節か」。小節を押すとそこから録音が鳴る・範囲を選んでループ・鳴っている小節を追う。浄書の絵には何も描き足さない |
   | ヘッダの下の帯（録音があるときだけ・畳める） | 「録音のどこか」。波形と小節・拍・section のマーク・再生位置。M・B・S で打ち、ドラッグで直す。人が確かめたマークは濃く、確かめていないマークは薄く。ループの範囲 |
   | ツールバー（1 行のまま） | 足すのは 2 つだけ: 鳴らす物の切り替え（楽譜の音／録音）と、録音パネルを開くボタン（Practice と同じ形。速度・セント単位の音高・オクターブ・音高と速度の連動・EQ） |

   楽譜には時間の軸が無い（小節の幅は音符の数で決まる）ので、マークを打つ・直す・テンポの揺れを見るのは帯の仕事。
   帯は再生位置のまわりを拡大して見せ、全体は細い全景で示す（3 分の曲を 600px に並べると 1 小節が約 6px で打てない）。
   下のパネル（ターミナルの場所）に出す案は、楽譜から目が離れるので採らない。

4. **（2026-11-15・同じ便）伸縮のエンジンは Signalsmith Stretch（MIT・公式の Web 版を同梱）。**
5. **m4a は (a)**: Windows では LSP（.NET）が Media Foundation で復号し、拡張の保存場所（`globalStorageUri`）に置いて webview に渡す。
   mac／Linux の m4a は最初の版では受けない（受けないと言う）。wav・mp3・flac・ogg は webview が自分で復号する（§3 で実測）。
6. **最初の版は §4 の 1〜4。**
   小節を打つ操作について（オーナー 2026-11-15「Transcribe! を意識しすぎな感じもするが、便利な機能だから拝借してよい」）:

   - **ツールバーの波形のボタン（録音で鳴らす切り替え）は外す**（オーナー決定。`d7575015a` の「押せば鳴る」はそれまでのつなぎ）。録音パネルのボタンは残す。
   - Tempo のスライダーは両方に効く（録音も同じ倍率で伸縮・音高は保つ）。
   - 楽譜の音符の時刻を、隣のファイルの小節の秒で小節ごとに伸び縮みさせて、録音の揺れに合わせる（S4 の小節 ↔ 秒の対応）。小節の位置が無い譜面（Attach しただけ）は録音だけが鳴る。

## 4. 最初の版の案

1. 入口: 「Attach Recording…」（wav・mp3・flac・ogg）と、Orecchiante の `x.orecchiante.json` を読むこと。変換メニューは D3 の後（§2）。
2. ツールバー: 鳴らす物の切り替え（楽譜の音／録音）と録音パネル（速度・半音とセント・オクターブ・連動のオン／オフ）。
   - **楽譜の移調に録音がついて行く**（オーナーの決定 2026-11-16）: 録音は楽譜の書かれた調で録られたものとして、ファイルの `transpose` と描く score の `transpose` の半音だけ、パネルの高さに足して鳴る（速度は変えない。連動オンでも stretch）。パネルに `Chart +2` の行。LSP `lilysharp/svg` の `ChartTranspose`。楽譜の絵を表示だけ移調する案は取り下げ（画面と PDF が食い違う事故のもと）。
   - **録音の場所**（Orecchiante の依頼 6・オーナー決定 2026-11-16＝「隣のファイルはファイル名だけ」を改めた）: 隣のファイルの `audio` は、録音が楽譜の隣ならファイル名、別のフォルダなら楽譜のフォルダからの道（`../Music/x.mp3`・区切りは `/`）、ドライブが違えば絶対パス（`recordingCore.ts` の `audioRef`／`resolveAudio`）。変換は毎回書き出すフォルダを尋ね（初期値は録音のフォルダ）、録音は写さない（0.3.0 より前の Orecchiante のときだけ写す）。Attach Recording… も写さない。見つからないときは「Locate Recording…」で選び直す。録音を動かしたり名前を変えたりすると、ワークスペースの隣のファイルを書き直す。楽譜を別のフォルダへ動かすと、隣のファイルが付いて行き、道を書き直す。
   - パネルの設定（速度・オクターブ・半音・セント・連動）は録音ごとに `workspaceState` へ自動で保存し、次に開いたとき戻す（recording.ts `keepRecordingSettings`）。
   - ★ **2026-11-19 オーナー決定＝パネルに残すのは Octave だけ**（上の 2 行と §2 の「速度・半音とセント・連動」より新しい）: Speed・Semitones・Cents・Pitch with speed・`Chart +2` の行は撤去。遅くするのは Tempo（楽譜と録音が一緒）、移調は楽譜の `transpose`（録音がついて行くのは今までどおり・行だけ消した＝Octave の行のツールチップが移調の量を言う）。**Octave は残す**（オーナー: エレキベース奏者＝低い音は音程が分かりにくく、1 オクターブ上げると分かる。使用頻度が高い）。保存は録音ごとに `{ octave }`（前の版の speed・semitones・cents・linked は読まない）。`recordingCore.ts` の `RecordingSettings` は `{ octave, chart? }`、`recordingPlan` はどちらも音高だけに掛け、速さは Tempo だけ。⚠️ Tempo の下限は 50%（Speed は 25% まであった）。
   - ★ **調律（`tuning`）は使わない＝見送り（オーナー決定 2026-11-19）**。同じ日に 3 つの形を試して、全部やめた:
     - ⑴ **自動で A440 に戻す**（`tuning` の分だけ音高と速度を一緒に＝伸びたテープを当時の演奏に戻す。旧「Cents ＋ Pitch with speed」の置き換え）→ やめた。オーナー: 「昔の演奏は、そもそもチューニングがくるっている場合もある」＝Orecchiante は A440 からのずれを測るだけで、テープの伸びと元の調律を見分けられない。
     - ⑵ **「Tune to A = 440」のボタン**（既定オフ・±10 セント以上のときだけ出す）→ 作って、消した。きっかけは「今宵の月のように」（1997 年・`tuning` 4）でボタンが出たこと。閾値で隠した後、オーナーが「本当に必要な機能なのか」と問い、除去を決めた。
     - ⑶ **楽譜の音を録音の調律に合わせ、その高さ（「A ≈ 443 Hz」）を練習する人に見せる**（クラシックの A = 442 への対処としてオーナーが出した問い）→ 作らない。理由: ⒜ 困った場面がまだ無い ⒝ Orecchiante の `tuning` を確かめたのは 24 曲だけで、RWC のスタジオ録音が −9〜+4 と読まれる＝442（約 +8 セント）と 440 を見分けられず、読み違えに合わせるとかえって濁る ⒞ 楽譜の音を数セント動かすには音源（SoundFont）・歌声（Cantoria）・MIDI 出力・書き出しの全部に手が要る（手段は未調査）。
     - **再検討の条件**: 10 セント以上ずれた録音を実際に練習に使って困ったとき／Orecchiante の測定を既知の録音（440・442 など）で確かめられたとき。そのときの形の第一候補は「基準は 1 つ・動かす側を選ぶ」＝録音を 440 に動かす（調律を変えにくい楽器向け）か、楽譜の音と自分の楽器を録音に合わせる（高さを表示）か。Orecchiante は `tuning` を書き続けている（隣のファイルの項目はそのまま・Lily# が読まないだけ）。
3. 楽譜: 小節を押すとそこから録音、選んだ範囲はループ（今の Practice の Loop と同じ選び方）。
4. 帯: 波形・小節のマーク・再生位置。**M で小節を打つ・ドラッグで直すまでは最初の版に入れる**（Orecchiante を使わずに録音を付けた人は、小節を打たないと小節から鳴らせないため）。
5. 次の版: 拍（B）・section（S）・範囲のテンポ・名前つきのループ・EQ とカラオケ・ショートカットの設定・ペダル。

**決めてほしいこと**: ⑴ エンジン（推奨 Signalsmith）／⑵ m4a の扱い＝(a) Windows では LSP（.NET）が Media Foundation で復号して拡張の保存場所（`globalStorageUri`）に置く・mac／Linux の m4a は最初の版では受けない、(b) Orecchiante が入っているときだけ受ける、(c) 最初の版は m4a を受けない／⑶ 最初の版の範囲（上の 1〜4）。

**S4 の実際の形（第1285・§1 7 と一緒に）**:
- 録音は Practice の Parts の最後の行（`Recording`・トグル＋フェーダー）と録音パネルの一番上（`recOnBtn`・`recLevelSlider`＝同じ値）。ツールバーの波形のボタンは外した。

## 7. 書き出し（WAV・MP3・MP4）に録音を入れる（オーナー報告 2026-11-16・第1286 で実装）

オーナー決定（2026-11-16）: WAV／MP3 にも MP4 と同じく入れる・MP4 のコード名は全部の楽譜で光らせる。

- **時刻**: webview の `practiced()` と同じ＝`recordingExportCore.ts` の `recordedExportPlan`。音符と拍を `timeWarp(beats, BarEnd, bars)` で録音の秒へ移し（`warpNotes`／`warpBeats`）、`recordingPlan(sound, practice.speed).rate` を速さにして `exportPlan` に渡す（2026-11-20 から `warpFit` は掛けない＝§5 の速さ）。録音の秒 0 はリストの 0（Count-in の後＝`Lead`）。
- **（2026-11-20・Shosa の依頼 3）書き出しは速さ 100%・Count-in なしなら元の録音と同じ秒の上**。頭が 34 ms 遅れていた原因は 2 つ（Lab `sessions/p1339/align`、ヘッドレス Edge と ffmpeg で実測）: ⑴ 書き出しの MP3（lamejs）に LAME タグが無く、復号が 1105 標本（25.1 ms）遅れる → `audioRenderCore.withGaplessTag` が Info フレーム（遅れ 576・末尾の詰め物・CRC）を先頭に置く＝ffmpeg と Chromium の復号で 0 標本差・長さも入力と同じ。タグを読まない再生機では先頭に 26 ms の無音のフレームが 1 つ増える（LAME の普通の MP3 と同じ）。⑵ `RecordingPlayer.render` のリミッター（DynamicsCompressor）の先読み 6 ms（44.1 kHz で 264 標本）→ 伸縮もパートの和も無い録音はリミッターを通さない。通すときはその分を頭から切る。録音の MP3 の復号は Chromium も遅れを除いている（ffmpeg と 0 標本差）。
- **（2026-11-20・Shosa の依頼 4）歌い手の声も録音の揺れに付いていく**（下の「残る穴」を埋めた）: 拡張は、録音が楽譜と鳴っているページ（`PracticeState.recording`）の声を頼むとき、楽譜の拍（`lilysharp/playback` の `soundingOnly`）と録音の小節から `timeWarp` を作り、音節の始めと終わりを録音の秒へ移してから Cantoria に渡す（`singerCore.voiceOnWarp`）。声の鍵が変わるので別の声として歌い直す。ページは声がどの warp で歌われたか（`recordingCore.warpKey`）を持ち、今の warp と同じ声だけを鳴らす（違えば歌い直すまで楽器が代わる）。録音のオン・オフや小節線の移動は `practiceState` で拡張に届き、歌い直す。書き出し（`singJobs`）も、録音を入れる仕事では同じように移す。
- **配線**: webview は録音が楽譜と鳴る状態（オン・読み込み済み）のとき `practiceState.recording`（小節・`recSound()`・フェーダー）を送る（`postPracticeState`・`showRecording` と読み込みの完了でも送る）。LSP の `PlaybackExport.BarEnd`。拡張の `practisedJobs` が `RecordingPlay` を付け、歌い手の後の `recordJobs` がプレビューに `renderRecording` を頼む → webview は `RecordingPlayer.render`（同じエンジン・rate・shift・gain・リミッター、フェーダーは除く）を OfflineAudioContext で描き、10 秒ずつ `recordingRendered` で返す → `AudioJob.Recording`（ステレオ）→ `renderAudioFiles` が `mixInStereo` で楽譜の音に足す（ゲインはフェーダー ÷ プレビューの master 0.9＝`PREVIEW_MASTER`、その後 `fileLevel`）。MP4 は `writeVideos` が同じ WAV を使い、長さは録音の終わりまで（`fileSeconds`）。プレビューが無い・描けないときは録音なしで書き、出力チャンネルに理由。

## 8. 録音をパートごとにオン・オフ（Orecchiante REQUESTS 16・第1288）

オーナーの希望「レコーディングのオンオフをパートごとに行えるようにすべきだ。耳コピにとても便利だ」・「特定の楽器に寄せない」。Orecchiante 0.7.0 は変換のたびに録音を分けて書く: 隣のファイルの `parts` が `{"drums": "x.parts/drums.flac", "bass": …, "other": …, "vocals": …}`（順はこのまま・道は `audio` と同じ読み方）、各パートは FLAC・モノラル・16 bit・44.1 kHz・録音と同じ長さで録音の秒の上（Orecchiante SIDECAR.md）。Orecchiante は次に 6 パート（guitar・piano を足す htdemucs_6s）を予定。

**オーナー決定（2026-11-17・Claude の案を了承）**:
1. 全部オン（フェーダーも全部 100%）のときは**元の録音**を鳴らす（分離の誤差 32 dB を避ける）。1 本でもオフか 100% でないときは、残りのパートの和を鳴らす。
2. 伸縮の重さは実測して決める（下の「測ること」）。
3. 楽譜や隣のファイルが別のフォルダへ移る・コピーされるとき、`parts` の道も `audio` と同じ規則で書き直す（フォルダの中身は動かさない＝録音と同じ扱い）。
4. モノラルで足りる（全部オンのときは元の録音＝ステレオのまま）。
5. パートは `parts` に書かれた**数と順**で並べ、名前で決め打ちしない（4 でも 6 でも同じ道）。

**形**:
- 拡張: `parseRecording` が `parts` を `{ name, file }[]`（書かれた順）で読む。`sendRecording` は録音の音を送った後に、各パートのファイルの中身を `recordingParts` で送る（webview が自分で復号できる形式だけ・見つからないパートはその名前と理由）。送り直しの鍵にパートのファイルの stat も入れる。
- webview の再生（`RecordingPlayer`）: パートを N チャンネルの 1 本の `AudioBuffer` にまとめる（チャンネル i がパート i）。鳴らすときは伸縮のノード 1 つに N チャンネルで渡し（Signalsmith の `outputChannelCount: [N]`）、出力を `ChannelSplitter` で分けてパートごとの `GainNode`（オフは 0・フェーダー 0〜2）を通し、録音の gain（リミッターの手前）で足す。連動オン（再標本化）も同じ N チャンネルのバッファを `AudioBufferSource` で鳴らして分ける。1 つのノードなので N 本の時刻は標本単位で揃う。パートのノードはパートを 1 本でもオフにしたときに初めて作る（使わなければメモリは増えない）。
- 元の録音とパートの切り替え（全部オン ⇄ どれかオフ）は、鳴っている位置から鳴らし直す（楽譜と一緒なら `practiceChanged`）。パートの間のオン・オフとフェーダーは、鳴らし直さずに gain を変えるだけ。
- UI: Practice の Parts の「Recording」の行の下に、パートごとの行（トグル＋フェーダー・字下げ）。録音パネルの一番上の Recording の行の下にも同じ行（2 か所は同じ値を見せる）。「Reset parts」はパートを全部オンに、「Reset faders」はパートのフェーダーも 100% に。パートの状態はページのもの（保存しない・Practice のパートと同じ）。
- 書き出し（§7）: `RecordingPlayer.render` も今のパートの状態で描く（全部オンなら元の録音）。

**測ること**（オーナーの静かな窓をもらってから・Lab `p1288/parts/measure.mjs`）: ヘッドレス Edge で、30 秒を 0.8 倍で伸縮する時間（元の録音 2ch／パート 4ch を 1 ノード／6ch／両方／1ch のノード 4 つ）と、復号してノードに渡した後のプロセスのメモリ（5 分の曲で 1 パート約 53 MB の float、ノードが WASM の中へもう一度写す）。重すぎれば「和にしてから 1 ノード 1ch で伸縮」に替える（オン・オフとフェーダーは和を作る前に掛ける＝切り替えのたびに和を作り直す）。

**残る穴（作る前から分かっているもの）**: 録音が別のドライブで `audio` が絶対パスのまま変わらない移動では、`parts` の道は書き直されない（`audio` の書き直しに乗せているため）。

**実際の形（第1288）**: 上の形のまま。網は `recordingCore.test.ts`「the recording's parts」（6 パート・順・壊れた項目・書き戻し・移動とコピー）。実物の VS Code（CDP・Lab `p1288/e2e/cdp-parts.mjs`・Orecchiante の作業場の My Life 284 秒＋4 パート）: パートは録音の約 1 秒後に読み込み済み（4 チャンネル・同じ長さ）／Practice と録音パネルに 4 行ずつ／書き出し用の描画の RMS（最初の 30 秒）＝全部オン（元の録音）0.1207・パートの和（フェーダー 1 本 99.9%）0.1202・bass だけ 0.0437・bass 以外 0.1096・全部オフ 0／鳴らしながら bass オフ＝元の録音の 2.29 秒からパートの 2.30 秒へ鳴らし直し・続けて drums オフ＝鳴らし直さない・全部オンに戻す＝元の録音へ同じ位置から。パネルが 60vh を越えて縦にスクロールし横のスクロールバーも出た＝`.practice-panel { scrollbar-gutter: stable }`。

**実測（2026-11-17・オーナーの静かな窓・Lab `p1288/parts/measure.mjs` → `result.json`・ヘッドレス Edge・48 kHz で復号）**:
- 重さ（30 秒を 0.8 倍で伸縮する時間）: 元の録音 2ch 529 ms（実時間の 1.8%）／パート 4ch を 1 ノード 965 ms（3.2%）／6ch 1391 ms（4.6%）／1ch のノード 4 つ 1218 ms（4.1%）。鳴るのは元の録音かパートの片方だけ＝1 コアの 5% 未満。1 ノードにまとめる方が軽い。
