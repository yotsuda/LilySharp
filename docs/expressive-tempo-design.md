# rit.・accel.・rall. とフェルマータで時間を動かす — 設計

評価 5 の B1（4 人の書き手が全員挙げた・評価 4 でも）。オーナー決定 2026-11-23: 「まずはテンポ系だけ」
（アルペジオのロール・トリル・ゴーストノート・pizz./arco の音色は作らない）。フェルマータの止め方は
「2 倍は止めすぎでは、妥当な止め方は」への Claude の答え＝**1.5 倍**（下）。

## 1. 今（2026-11-23 まで）

- `@rit` … `@!rit`（`@accel`・`@rall` も）は文字と破線を描くだけ。MIDI・プレビュー・WAV は時間を変えない。
- フェルマータは、その音だけを半分長く鳴らす（`ApplyArticulationType` の 150%）。ほかのパートは先へ進む
  （第1363 からは次の音で切る）＝時間は止まらない。文書は「描くだけ」と言っていた（評価 5 の A6）。

## 2. 決めたこと

- **テンポで表す**（全パート共通）。MIDI の指揮者トラックのテンポの事象＝`.mid`・プレビュー・WAV・MIDI 出力が
  同じ時間で鳴り、反復の展開（`PlayedTimeline.Unfold`）がそのまま演奏順に写す。音符の長さは変えない。
- **rit.／rall.**: 線の始まりの音の頭から、`@!rit` を書いた音の終わりまで、テンポをなめらかに落とし、
  終わりで**元の 70%** の速さ（16 分音符ごとに 1 つのテンポの事象・速さで直線）。
- **accel.**: 同じ区間で**元の 130%** まで上げる。
- **線の後は元のテンポ**（暗黙の a tempo）。Lily# に「a tempo」の書き方は無く、線は `@!rit` で閉じる＝
  閉じた所で戻るのが書き手の意図に近い。続けて遅いままにしたいなら、そこに `tempo` を書く（書いた `tempo` は
  線の後の戻しより強い）。⚠️ Claude の判断。
- **フェルマータ**: その音（休符・全休符も）の書いた長さの間、**時間を 1.5 倍に止める**＝テンポを 2/3 に。
  その音自身を伸ばすのはやめる（二重に伸びる）。2 倍は遅い曲の長い音で長く感じる（オーナーの指摘）。
  1.5 倍は今までの「音を半分長く鳴らす」と同じ長さ＝聞こえる長さは今までどおりで、ほかのパートも一緒に待つ。
  同じ時刻のフェルマータは 1 つ（どのパートに書いても同じ）。rit. の中のフェルマータは、rit. のその時点の
  テンポに 1.5 倍を掛ける。
- **どのパートに書いても全体に効く**（テンポは 1 つ）。歌詞の行・コード行の `@rit` は今までどおり描くだけ。
- **書き出し**: MusicXML は今までどおり（`<words>` と線）。`.ly` は文字だけ（双子は絵を測るもの）。

## 3. 実装

- `MidiExporter`: 音の歩き（`ProcessNode` の onset の包み）で、音・和音・休符に付いた `@rit`／`@rall`／`@accel`
  の始まり（構文は `ArticulationSyntax`）と `@!…` の終わり（`MusicMarkSyntax`）、フェルマータの区間を、印刷どおりの tick で集める。
  フェルマータは `ApplyArticulationType` が通るたびに印を付ける＝和音のメンバーのもの・空の和音から次の音へ渡ったものも拾う。
  段の速さは区間の最初の段が元のテンポちょうど、最後の段（終わりの 16 分前）が到達の速さ。全パートが同じ線・同じフェルマータを書いても 1 つ。
  歩きの後・`Unfold` の前に、元のテンポの地図から rit. 系の段階のテンポを書き、その上にフェルマータを掛ける
  （`ApplyExpressiveTempo`）。`ApplyArticulationType` のフェルマータは 100% に。
- 閉じない `@rit` は今までどおり検査が言う（LYS…）＝鳴らさない。

## 4. 作らないもの（オーナー決定 2026-11-23）

アルペジオのロール・トリルの交互音・ゴーストノートの弱さ・pizz./arco/mute の音色・`@rit(…)` の量の指定。
