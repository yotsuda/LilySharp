# ドラムを打ち込み風に書く `steps { }`

Orecchiante の依頼 24（`C:\MyProj\Orecchiante\docs\repro\lilysharp-requests-2026-11-26-drum-steps.md`）。
オーナー決定 2026-11-26（第1399）: 入れる。ゴーストは (b)＝ドラムの括弧つきの音は書き方に関わらず弱く鳴らす。
ほかは Lily# の勧めどおり。

## 1. 形

```
steps [拍] { 太鼓 "パターン"  太鼓 "パターン" … }
```

- 1 文字が 1 つの刻み: `.` 打たない・`x` 打つ・`X` アクセント・`g` ゴースト・`o` ハイハットを開く・`f` フラム。
- 空白で区切ったかたまりが 1 拍（空白は必須）。`|` で小節を区切る（最後の `|` は書いてもよい）。
- 拍の長さは `steps` の後に書く（既定は 4 分）。`steps 4.`（6/8・12/8）、`steps 8`（7/8 など 8 分が拍）、`steps 2`（2/2）。
- かたまりの文字数: 拍が付点でなければ 1・2・4・8（均等）と 3・6（3 連）。付点の拍なら 1・3・6（3 連なし）。
- 行の名前は今の太鼓の名前。全部の行で小節の数と、小節ごとの拍の数が同じ。

## 2. 決めたこと

1. **拍は拍子から取らず、書いたもの（既定 4 分）。** 承認した案は「拍は拍子の拍」だったが、変えた。理由: エディタの
   増分の解析は、変わっていない最上位の項目（phrase など）の木をそのまま使う（`IncrementalReuseMap`）。読みが離れた
   場所の `time` に左右されると、`time` を書き換えても phrase の読みが古いまま残る。phrase は拍子を持たず、どの拍子の
   section で鳴るかも決まらない。そこで読みは文字列と `steps` の行だけで決まる形にした。合わない拍子で使うと、今の
   小節の長さの検査（LYS2006 など）が出る。`steps 8` で 7/8 の 2+2+3 も 3+2+2 も書ける（拍子ごとの決まりが要らない）。
2. **木は `drums { }` と同じ。** パーサーが各行の文字列を、その行を `drums { }` で書いたときの字句に置き換えてから
   ふつうに読む（`Parser.Steps`・`StepsPattern`）。開きの語は `DrumsOpener`（綴りは `steps`）なので、紙・MIDI・
   MusicXML・LilyPond・検査は何も変えずに読む。打つ音は「綴りは `hh`・原文は `x`」の字句
   （`SyntaxToken.Spelled`、`LeftOut` を一般にしたもの）で、自分の文字の上にある＝data-pos・エラーの位置・原文の往復は
   原文のまま。長さ・休符・3 連・装飾音は幅 0。伸ばしの `.` と空白は前の字句の trivia（`StepsHoldTrivia`・空白）。
   引用符はかっこ `{` `}` の原文。
3. **音の長さ**: 打った音は同じ拍の次の打撃まで、または拍の終わりまで。拍の頭の打たない刻みは休符。拍の打撃が
   粗い格子に乗るなら粗い格子で書く（`x..x..` は 8 分 2 つで 3 連にしない）。音符と休符の長さは付点まで
   （付点 2 つは使わない＝余りは休符）。
4. **休符**: 空の拍は 1 拍の休符。空の小節は 1 つの休符（書ける長さなら）。4 拍の小節では 1–2 拍・3–4 拍が空なら
   2 拍の休符。3 拍の小節では続く 2 拍の空を 1 つに。
5. **ゴースト (b)**: `@parenthesize` のついたドラムの音（和音の中の音も）は強さを 2/5 にする（`MidiExporter.IsGhost`）。
   `steps` の `g` も `sn16@parenthesize` も同じ。音高のある音の括弧は今までどおり（編集者の注）。
6. **`o`** は `hh`（と `hho`）の行で `hho`。ほかの行は警告 LYS0049 で `x` として鳴らす。
7. **エラー**は LYS0048 1 つで、行・小節・拍・刻みを名指す: 知らない記号、拍に入らない文字数、空の小節、行どうしで
   小節や拍の数が違う、太鼓でない行の名前、文字列のない行、太鼓のない文字列、書けない拍の長さ。
8. `steps` は `{` か拍の前だけの語。`steps` という名前の phrase は今までどおり呼べる。

## 3. 入れなかったもの・残り

- ~~依頼 §4 の `drums { }` ⇄ `steps { }` の変換~~＝第1400 で入れた（`Editing/DrumStepsConverter`・Ctrl+. の
  「Convert to Drum Steps steps { }」「Convert to Drum Lines drums { }」）。steps へ: 線（phrase の線も）の打撃を
  時刻で集め、太鼓ごとの行（最初に出た順・`hho` は `hh` の行の `o`・`@accent`→`X`・`@parenthesize`→`g`・同じ太鼓の
  `acciaccatura`→`f`）。小節は最初の線の小節線。拍はその場の拍子（section の前の `time`、なければファイルの）で、
  複合拍子なら付点（`steps 4.`）。拍ごとに打撃が乗るいちばん粗い格子（全部の拍に 1 つの格子が合えばそれ）＝行が
  揃う。音の長さは保たない（steps の規則になる）。書けない表（`up`/`down`・アクセントとゴースト以外の印・格子に
  乗らない打撃・線どうしで小節線が違う）には出さない。lines へ: パーサーが読んだ音をそのまま書く＝絵も音も同じ。
- ~~拍子と合わない小節の専用の文~~＝第1400 で入れた: 短い・長い小節の警告（LYS2001／LYS2002・最初の小節の弱起の
  勧め）の後ろに「the steps chart has 3 beats of a quarter, and this bar holds 4」を足す（小節に書いた表も、小節が
  鳴らす phrase の中の表も・`MeasureValidator.StepsNote`）。6/8・12/8 で 4 分を数える表は長さが合ってしまう
  （4 分 3 つ＝6/8）ので、警告 LYS2024 で `steps 4.` を勧める（拍を書いた表には言わない）。付点の拍を単純拍子に
  書いた表には `steps { }` を勧める。
- 拍をまたいで伸ばす音（`x... ....` を 2 分にする）は書けない。要るなら `drums { }`。
- 網: `LilySharp.Tests/DrumStepsTests.cs`（同じ `drums { }` の LilyPond と MIDI に一致・往復と位置・増分の解析・
  エラーの文・ゴーストの強さ）。
