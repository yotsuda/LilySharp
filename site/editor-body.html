Install and open

Lily# Studio is the editor for Lily#: an extension of Visual Studio Code that brings the compiler, a live score preview that plays, and the AI features. Installing it takes one search in VS Code's Extensions view — Get started walks through it, and through a first score. Open any .lys file and the language server starts, with the score beside it. The keys to know:

KeyDoes
Ctrl+Spacelist what can come next — words, names, chords, marks; in an empty file, the lessons — below
Ctrl+Shift+Vopen the score preview
Ctrl+K Vopen it beside the source
Alt+P (hold)sound the note under the caret
Alt+Mplay the measure the caret is in
Ctrl+Shift+Up / Downstep a note to the next note of the key, a chord shape, a tempo by 1, a key a fifth, a clef, a dynamic, a time, an octave or a transpose — below
Ctrl+Shift+PageUp / PageDownstep a note an octave mark, a chord shape, or a tempo by 10; switch a key to its parallel / relative key, a treble or bass clef an octave, a dynamic a level, a time to the next common meter, an octave by 1 or a transpose an octave
Ctrl+IAsk AI…: say what to change, a selection as a hint of where — below

On macOS read Cmd for Ctrl in the first two and the last; the stepping keys are Ctrl+Shift+Up/Down and Ctrl+Shift+PageUp/PageDown (the Control key) there too.

Typing aids you might not notice

A note is written in one order — pitch, octave marks, duration, dots, then its string number, annotations and marks: cis'4.\2@accent(. The editor knows that order, so a mark typed anywhere on the note lands in its slot, and the caret stays where you pressed the key. You never have to move to the right spot first. In the examples, | is the caret.

Octave marks land after the pitch

Type ' or , with the caret anywhere on a note — at its start, in the middle of its name, after its duration or dots, or among its annotations and marks — and the mark is inserted after the pitch letters and the marks already there, before the duration.

BeforeTypeAfter
c|is4.'c|is'4.
cis4.|'cis'4.|
cis4.@accent|'cis'4.@accent|
c,4|'c4| — the opposite key cancels one mark
<c e g>4|'<c e g>'4| — the whole chord

Marks stack from wherever the caret rests (' twice gives c''4). Inside a chord's brackets the mark is the member's and is typed where you press it (<c e| g> → <c e'| g>); the chord as a whole takes one at its < or after its >. A rest takes no octave mark, so there the key types as pressed.

A duration digit replaces the duration

Type a digit with the caret anywhere on a note, rest, chord or slash note and it goes to the duration slot, and what it leaves there is always a real duration — 1, 2, 4, 8, 16, 32, 64 or 128. A digit that makes one together with the digits already there extends them; otherwise it replaces them. Dots stay.

BeforeTypeAfter

Directly after the digits a digit extends them only when the result is a duration (c1| + 6 → c16, c3| + 2 → c32). Anywhere else on the note a 1, 2, 4 or 8 starts a fresh duration (c1.| + 2 → c2.), while a 3 or 6 — no duration by itself — extends when it can (c1.| + 6 → c16.). A 3 or 6 that extends into nothing is completed to the only duration it can start: 32 or 64. Retyping the duration a note already has changes nothing. A digit that begins no duration — 5, 7, 9, 0 — leaves the note unchanged and says so in the status bar: on a note it could only write an error such as c45.

A 128th cannot be typed digit by digit, since c1| + 2 is already c2: paste 128, type it with the aids turned off, or type 8 after a 12 that is already there. Digits inside a chord's brackets (scale degrees), inside an annotation's parentheses (@finger(5)) and outside notes (time 5/4, R1*5) are typed as pressed.

Several cursors. With more than one cursor, the octave marks, digits, dots, \ and @ work at each cursor on its own note, all in one undo step: c4| d1| /4| + 6 → c64| d16| /64|. Two cursors on the same note have no single answer, so there the key is typed as pressed at every cursor. The bracket, slur, beam and tie keys are single-cursor: with several cursors they type as pressed.

When it steps aside. With a selection the key replaces the selection, as anywhere in VS Code. Keys inside strings and comments, and outside notes — time 4/4, tuplet 3/2, a title — type as pressed. A slash note takes durations, dots, ties, slurs and beams like a note but has no pitch, so ', , and \ type as pressed on it, as on a rest. Every aid is one undo step with the keystroke. To turn all of it off, set lilysharp.typingAids.enabled to false (Settings → Lily# → Typing Aids): every key then types exactly as pressed.

The preview

The score redraws as you type, not when you save: a keystroke reparses only what it touched, and only the systems whose width changed are laid out again.

  • It opens by itself and follows you. Opening a .lys file opens the preview beside it (lilysharp.preview.openOnOpen); switching to another .lys turns the same preview to it, each file keeping its own zoom and scroll, and while it plays it waits for the music to stop. The lock at the top right of the preview keeps it on one file — to compare two scores, lock one and switch to the other: its preview opens beside the locked one. Bringing a locked preview forward brings its file's tab forward too, and a .lys opened while the preview has the focus opens among the scores, not over the preview.
  • Source and score are linked both ways. The note under the caret is highlighted in the score, and a selection highlights every note in it. Click a note, a tie, a slur, a clef or a key signature in the preview to jump to the text that wrote it, or a bar beside its notes to put the caret in that bar.
  • Bars can be selected on the score. Shift+click a bar or a note to extend the selection from the last place clicked, Shift+drag across bars, or right-click Select This Bar; the bars are lit pale blue, and Esc or Clear Selection clears them. ▶ then plays them and the AI takes them as its hint. A plain drag scrolls the sheet, and Ctrl+wheel zooms it.
  • The header holds, from the left: the picker for which score the preview shows, Export, ✨ Ask AI, Range, ▶ and ⏹, the practice menu, how long the score plays (3:42), and the pages. On a narrow pane its groups wrap onto the next row rather than squeeze.
  • It plays. ▶ plays the score the preview shows — that score's parts, under its form — or the bars selected on it, each note lit as it sounds, with each part's own General MIDI sound. Right-click a note or a bar for Play from Here (from that note, or from the bar's first), and anywhere for Stop Playback, Fit Width and Reset Zoom. More in Playback and practice.
  • Its pages stand apart as sheets of paper, and an exported PDF has pages of the paper's real size.
  • Its sound is a SoundFont synthesizer. Out of the box it plays the General MIDI bank your computer already has; for fuller instruments, install a free sound font — Sound fonts, below. A browser lets sound start only once you have clicked or typed in the preview itself — the status bar says so when a note comes first.
  • It exports. Lily#: Export writes PDF, SVG, PNG, LilyPond (.ly), MusicXML, MIDI or a VOCALOID sequence — from the preview (the score it shows, under that score's own form), the command palette, or by right-clicking .lys files in the Explorer (every score of every selected file, into one folder). Every door writes the same file as lysc.
  • Red rings mark the @todo notes, with their memos in the staff's margin. Exporting an SVG, PNG or PDF of a score that has any asks whether to draw them (lysc svg --todo does on the command line).
  • Its colours follow VS Code's theme, or stay light (the printed page) or dark: lilysharp.preview.theme.

Playback and practice

▶ plays the score, or, with bars selected on the score, those bars — every part sounding there, from where the bars first play, the notes lit as they sound. Hold Alt+P to hear the note under the caret; Alt+M plays its bar. Beside ⏹ stands how long the whole score plays, repeats and tempo changes included, kept up to date as you edit.

The practice menu drops down from the metronome button beside ⏹:

In the menuDoes
Tempoa slider from 50% to 150% of the written tempo; the button then reads 80%, and Reset puts it back
Loopplays the selected bars — or the whole score — round and round, through the music as written once (the score's own repeats inside it are not taken)
Metronomea wood block on every beat of the meter, the first of the bar louder; a pickup keeps the accents on the bar lines
Count-inone bar of clicks before the music comes in, in the meter where it starts: a pickup sounds over the count's last beats, and a start inside a bar comes in on its own beat — “1, 2”, and in on 3
Partsa toggle for each part — a chord row is one too — to silence it: sing or play yours against the others

The button stays pressed in while anything differs from the score as written, and a change made while it plays goes on from the same place. Play from Here on the right-click menu plays once from the note or bar, loop or not.

Each part's range

Range in the preview's header (a double-headed arrow beside a note) opens a panel over the score with each part's lowest (▼) and highest (▲) note, spelled as written, with the bar it stands in. Click one to see it on the score, with the editor's caret on it; a pitch written in several places says how many (2/3) and goes on to the next with each click.

Under them is the part's tessitura — where it spends four-fifths of its sounding time (G4–E5), which tires a singer more than the top note does — over a small chart of the time spent on each semitone from the lowest note to the highest. The panel follows the score picked in the header and every edit while it is open. The pitches are the sounding ones, with C4 for middle C.

Audition

With a preview open, edits sound through the preview's synthesizer, with the pitches the compiler plays: the note, chord or @chord shape the caret lands on (once per note, not on every arrow-key repeat), a note as you type it once its pitch and octave marks are in, and the result of every step. Nothing sounds while no preview is open. "lilysharp.audition.enabled": false turns it off; Alt+P and Alt+M keep working either way.

Sound fonts

The preview plays each part with the General MIDI instrument its midiInstrument or instrument preset names — the same sounds the exported MIDI asks for. Which recording of those instruments you hear is the sound font.

  • Out of the box Lily# plays the General MIDI bank your computer already has: on Windows the Microsoft GS Wavetable bank (gm.dls, 3 MB), on a Mac the bank of its DLS music device. Every instrument and drum kit is there, but the sound is small and dated. On Linux there is none, and the preview plays simple tones until you choose a font.
  • For fuller sound, download a free General MIDI sound font and choose it. Lily# does not bundle one, so Lily# Studio stays small and you pick the sound you like.
Sound fontSizeLicenceCharacter
MuseScore_General.sf336 MBMITfull and stereo; MuseScore 3's default — the one to try first
FluidR3Mono_GM.sf314 MBMITlighter and mono; MuseScore 2's default — for a slower computer
GeneralUser GSabout 30 MBits author's own, freebalanced; download from the author's page

The links are to the fonts' own publishers. More, and their licences, on MuseScore's sound font page; any .sf2, .sf3 or .dls General MIDI font works.

Setting one up

  1. Download the file (for MuseScore_General, click its name above). Keep it in a folder you will not tidy away — Documents\Sound fonts, say. Lily# reads it from there; it does not copy it.
  2. In VS Code, open the command palette (Ctrl+Shift+P, Cmd+Shift+P on a Mac), type sound font and choose Lily#: Choose Sound Font….
  3. Pick Browse for a file… and select the file you downloaded.
  4. The open previews switch to it at once — press ▶ to hear the difference. (A large font can take a moment to load when a preview opens.)

Switching back and forth. Choose Sound Font… remembers the last five fonts you have used and lists them under Default, so trying one against another is a pick, not a browse. A font whose file is not there when you open the list — on a drive that is not plugged in, say — is left out until it is back; the 🗑 button beside a font takes it off the list (the file stays where it is). To go back to the computer's own sounds, pick Default. The choice is the lilysharp.playback.soundFont setting, which holds the file's path.

MIDI output: a DAW, a VST host, or the computer's own synth

A sound font is one recording of the General MIDI instruments. For your own instruments — a sampled piano in a DAW, a VST or AU synth, a hardware module — have Lily# send MIDI instead: lilysharp.playback.midiOutput names a MIDI output port of your machine, and the ▶ button, Alt+P / Alt+M and the auditions all go there. The follow-along highlight runs as before.

  1. Have a port the receiver listens on. On Windows, Microsoft GS Wavetable Synth is there already — the computer's own synth, with no setup; for a DAW or a VST host install loopMIDI and add a port. On a Mac, switch on the IAC Driver bus in Audio MIDI Setup. On Linux the ALSA sequencer's clients are the ports: a FluidSynth / Qsynth, a DAW's input, whatever aconnect -l lists.
  2. In VS Code, open the command palette and choose Lily#: Choose MIDI Output…; pick the port.
  3. In the DAW, set a track (or a template with a track per part) to take MIDI from that port on the part's channel — the parts take channels 1, 2, 3… in score order, as the exported MIDI does, and the drums channel 10 — and press ▶.

Each part sends its General MIDI program (its midiInstrument or preset) when playback starts; a DAW track that keeps its own instrument ignores it. The auditions strike on channel 16. To go back to the sound font, choose The preview's own synth in the same picker. A port that is not there when you press ▶ — a device unplugged — makes the preview play its own synth, with the reason in the status bar. With both settings set, the port wins: the sound font plays only while no port is named or the named port is not there. The port is reached through each system's own MIDI API (winmm, CoreMIDI, the ALSA sequencer); it has been tried on Windows so far.

Stepping: Ctrl+Shift+Up / Down, Ctrl+Shift+PageUp / PageDown

Two pairs of keys that step what the caret is on, one notch at a time: Ctrl+Shift+Up / Down to the next note of the key, Ctrl+Shift+PageUp / PageDown by an octave.

OnUp / Down
a note, Ctrl+Shift+Up / Downmoves it to the next note of the key in force, spelled as the signature spells it: key c major walks the white keys, key f major steps a → bes → c. A minor key walks its signature and its leading tone too (key a minor: g → gis → a). A note off the key steps to the nearest note of the key that way (cis in C major: Up d, Down c). The note keeps its pitch — where the new letter would land in another octave, the marks are corrected (b' → c''). A chord member moves alone.
a chord as a whole (its > or its duration), Ctrl+Shift+Up / Downinverts it: Up raises the lowest note an octave (<c' e' g'> → <c'' e' g'>), Down lowers the highest; the other notes keep their pitches. Ctrl+Shift+PageUp / PageDown there move the whole chord (<c' e' g'>').
a note, Ctrl+Shift+PageUp / PageDownadds one ' (Up) or , (Down) — or takes away one of the other mark. Inside < > or << >> only the member under the caret moves; on the chord's > or its duration, the whole chord moves. With a selection, every note in it steps. It is a plain mark edit, so in relative mode the notes after it follow.
a chord name — @chord(Cm7) or a row's Cm7Up on a name with no shape writes its usual shape and the diagram appears (@chord(Cm7) → @chord(Cm7 x35343), G → G(320003)); further Ups and Downs walk the other playable shapes, frets 10–15 included; Down back at the usual shape removes it. The status bar says where you are: Cm7: shape 4 of 33 (x3x546).
a chord(…) itemsteps its shape the same way on the part's own instrument (from chord(C), Up writes the usual shape); Down stops at the usual shape, since the item needs one.
a tempochanges the metronome number: Ctrl+Shift+Up / Down by 1, Ctrl+Shift+PageUp / PageDown by 10 (tempo "Allegro" 4 = 120 → 130). Never the beat unit or a swing 16; it stops at 1.
a key, Ctrl+Shift+Up / Downmoves it a fifth round the circle — one sharp more, or one flat more: key c major → key g major, Down → key f major. The mode stays (a minor → e minor); it stops at seven sharps or flats. Only the signature changes, not the notes.
a key, Ctrl+Shift+PageUp / PageDownPageUp: the parallel key — same tonic, other mode (c major ⇄ c minor). PageDown: the relative key — same signature, other mode (c major ⇄ a minor). Major and minor only.
a clefCtrl+Shift+Up / Down: the clef for higher / lower notes — bass → tenor → alto → treble, stopping at either end — a part header's clef bass or a clef inside music. Ctrl+Shift+PageUp / PageDown: an octave — treble_8 ⇄ treble ⇄ treble^8, bass_8 ⇄ bass. Only the clef changes, not the notes.
a dynamic (the caret after its @)either pair steps it a level: pp → p → mp → mf → f → ff. On @cresc / @decresc, Up writes @cresc and Down @decresc.
an articulation (the caret after its @)either pair steps it along its group, Up towards the up-bow, the hammer-on, the longer, the stronger, the one above, stopping at either end: @downBow → @upBow, @pullOff → @hammerOn, @staccatissimo → @staccato → @portato → @tenuto, @accent → @marcato, @shortFermata → @fermata → @longFermata, @mordent → @prall, @reverseTurn → @turn, @trill → @pralltriller, @heel → @toe, @scoop → @plop, @fall → @doit, @breath → @caesura, @stemDown → @stemUp; Down goes back. A .up / .down stays. A mark in no group (@tap), a dynamic on no ladder (@sfz) and a bare @chord on a chord step the note, member or chord they are written on instead — <c' e' g'>@chord inverts it.
a timeCtrl+Shift+Up / Down: the beats by 1 (3/4 → 4/4). Ctrl+Shift+PageUp / PageDown: the common meters by the length of the bar — 3/8 2/4 6/8 3/4 2/2 4/4 9/8 12/8.
a part's octave Neither pair steps N by 1 (0 to 8); every bare note of the part moves with it.
an octave absolute / octave relative — the file's or one inside musicUp runs Convert Octaves to Absolute, Down Convert Octaves to Relative (either pair): the whole file is rewritten into that mode, every note keeping its pitch, and the file's octave line stays, naming the new mode. To change the word alone, type it.
a transposeCtrl+Shift+Up / Down: the target a semitone, spelled so the transposed key has the fewest sharps or flats (transpose d → ees); the status bar says how far. Ctrl+Shift+PageUp / PageDown: an octave mark (d → d').
the file's shifteither pair steps it a semitone (shift +1 → shift +2, −11 to +11) and the status bar names the key the piece lands in (shift +1: key c major -> des major). A top-level shift N moves the whole piece — every part, its own transpose included, the key signatures and the chord rows.
anything elseCtrl+Shift+Up / Down: nothing on Windows and macOS; on Linux, VS Code's own Add Cursor Above / Below. Ctrl+Shift+PageUp / PageDown: VS Code's own Move Editor Left / Right in Group (nothing on macOS)

All cursors step in one undo step. The shapes walked are the playable ones — at least three strings, chord tones only, the root lowest, within four frets and four fingers; stretch shapes (fretted frets five apart) are left out unless "lilysharp.chordShapes.includeStretch": true. Hover a chord to see what it draws, or what Up would write. In a score whose layout says chordDiagrams all a name already draws its usual shape, so there Up writes the next one. What a diagram is and which instrument it is drawn for: Chords and chord diagrams.

To use other keys, open Keyboard Shortcuts (Ctrl+K Ctrl+S) and bind lilysharp.stepSemitoneUp / lilysharp.stepSemitoneDown (a note of the key) or lilysharp.stepUp / lilysharp.stepDown (octave).

Completion, hover, fixes

  • Lessons. At the top level of a .lys file Ctrl+Space offers lesson-01-completion; type lesson for all twelve — from the completion list and the preview to drums, a band and a jazz chart. Each is a score whose steps are marked in red in the preview (@todo); picking one replaces the file, after asking. The same lessons are on the Learn pages.
  • Completion (Ctrl+Space) offers what can come next — after lyrics NAME it offers sings, then the part names in the file; inside layout { }, fonts { } and paper { } the keys and their values. In a section's music it offers the key's chords, and accepting one writes its notes (IIm7 in C writes <d f a c>); in a chords row or an @chord(…) it offers the key's chord names.
  • Hover names a chord — symbol, degree and pitches (Dm (IIm) D4 F4 A4) — and shows a chord's diagram, or how to add one. Over a phrase's name it shows the phrase's length, how often the file plays it and its source; a drum phrase adds its beat as a grid, one row per drum.
  • Value words complete too, and completing the keyword opens them at once: instrument (each preset with the clef, octave and tuning it sets), clef, key, tuning (each with its open strings), transpose (the targets from c, up and down, each with its interval — d up a major second, bes, down one), transposition (8va 8vb 15ma 15mb), and midiInstrument " the 128 General MIDI sounds. Hovering a preset lists what it sets.
  • Diagnostics as you type, worded to be acted on, and quick fixes where there is one obvious repair: a section written at different lengths gets Add bar lines (pad the shorter parts) and, when one part has cut it into sections, Split Sections to Match a Part; a name or value that differs from a real one only in case (@upbow, X32010) gets Write '@upBow'; a missing brace or rest can be inserted.
  • Rename a part or a phrase and every reference follows; go to definition, find references, the outline, folding, formatting and semantic colouring work as in any language.
  • A CodeLens over each section says how long it is, who writes it and how often each form plays it — or, when the parts disagree, each length and who writes it.

Ask AI and the AI features

The AI features use the language models VS Code offers — GitHub Copilot's, or those of another extension that provides models. Lily# Studio keeps no key or account of its own and has no telemetry; what happened is logged to an output channel on your machine.

Ask AI — Ctrl+I

Say what to change, in words and in any language: “add a bass line”, “make bar 5 a fill”, “harmonize the melody in thirds”, “transpose up a fourth”. Press Ctrl+I (Cmd+I) in the editor or the preview, click ✨ in the preview's header, or right-click the score: the menu names what it will take as its hint — Ask AI, This Note as a Hint…, This Bar…, the Selection…, or plain Ask AI… off the staves.

  • A selection is a hint of where to look, not a fence. Text selected in the editor, or bars, a bar or a note on the score, says where; the whole score stays open to change, so a harmony line can bring its new part and its score row with it. With nothing selected, the request is about the whole score.
  • The model reads the whole file — up to its input limit — with the Lily# grammar and the file's errors and warnings, and answers with edits: each a passage of the file and what replaces it. It works in absolute octaves, where every pitch says where it sounds; a file in relative octaves gets the change back in its own octaves on Accept.
  • Every answer is compiled before you see it. One that does not compile, adds warnings, or puts notes more than an octave away from the ones they replace is sent back with the reason, for up to two repairs. A notification says the step — reading the score, generating, repairing, rendering — and names the model.
  • You judge the music. The candidate panel engraves the score as it would be (After) and as it is (Before); switching keeps your place on the page. What the AI changed is green — only the notes it really changed — and 💬 under your request is its own word on what it did and why. ▶ (or Space) plays the side shown, or from a note you click; Ctrl+wheel zooms and a drag scrolls, as in the preview. Text after Accept opens the whole file as Accept would leave it, the changes marked — what is written in green, what goes struck in red — at the first change.
  • Ask Again… tells the AI what to change about the candidate, and its answer takes the candidate's place. Nothing changes until you Accept (Enter), and one Ctrl+Z undoes it; Reject (Esc) leaves the file as it is.

Fix the marks of a scan

For a score read from a scan, Fix OMR Marks with AI… proposes a fix for each bar the reader marked, with the scan's picture of the bar shown to the model and each proposal checked against the page before you see it; Edit Bars Beside the Scan opens the same panel to fix bars by hand — Scan Import.

Ghost completion

lilysharp.ai.ghostCompletion (off by default) suggests the next measure as ghost text just after you type a barline; each suggestion is compiled first and shown only if it is valid. It needs a fast model, so it has its own choice, lilysharp.ai.ghostModel. Switching it on offers to enable inline suggestions for .lys files — Lily# keeps them off there by default, because Copilot's own completion slowed every keystroke in a score.

Choosing the model

Lily#: Select AI Model… picks one for good: lilysharp.ai.editModel for Ask AI and Fix OMR Marks, lilysharp.ai.ghostModel for ghost completion. Without a choice, Ask AI takes the largest model on offer and passes over the small ones, which write poor Lily#; ghost completion takes a small, fast one.

Copilot Chat knows the grammar

Lily# Studio gives Copilot the Lily# grammar as an instructions file for .lys files, so Copilot Chat, agent mode and inline chat answer in Lily# instead of guessing LilyPond. (Copilot's as-you-type suggestions do not read instructions files — that is Copilot's rule.)

Other assistants and agents

The grammar Lily# Studio gives its models is a plain file in the repository, docs/GRAMMAR_FOR_LLM.md: the whole language, its gotchas and its reserved words, written for a model to read. Give it to any assistant that writes .lys, and let the compiler close the loop the way Lily# Studio does — lysc check song.lys prints every error and warning with its line and column, and exits non-zero on an error. For generated music, octave absolute keeps a wrong octave from cascading (Pitches and octaves).

There is no MCP server or packaged agent skill; the grammar file and lysc are the interface.

Scores in Markdown

A fenced block marked lily# in a Markdown file draws its score in VS Code's built-in Markdown preview, the way a mermaid fence draws a diagram. The fence holds a complete file — an existing .lys pasted as it is — and draws its default score (the unnamed one, else the first), laid out as a snippet: one page as tall as the music.

```lily#
part m { clef treble }
section A { m { c4 d e f | g1 | } }
form { ~A }
score { staff m }
```

The lysc command line

The same compiler, for batch work and scripts:

lysc check song.lys         // errors and warnings, nothing written
lysc svg song.lys           // song.svg, plus song-NAME.svg for each named score
lysc svg --score tab song.lys     // only the score named tab
lysc svg --todo lesson.lys        // with the @todo rings and memos
lysc svg --set music=Bravura song.lys   // another music font, over the file's
lysc check --todo-as-error song.lys     // fail while a @todo is left (--no-todo: say nothing)
lysc pdf | png | midi | xml | ly | vsqx song.lys
lysc wav --soundfont GeneralUser.sf2 song.lys   // the MIDI, played through an .sf2, as song.wav
lysc import score.musicxml  // MusicXML to .lys
lysc octave --absolute song.lys   // rewrite into absolute (or --relative) octaves
lysc harmonize song.lys     // suggest a diatonic chord track for the melody
lysc layout song.lys        // where the lines break, bars per system

-d DIR chooses the output folder, and --batch LIST runs a command over many files in one process. lysc --help lists the rest.
