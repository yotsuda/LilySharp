# 入力支援のテストケース

和音の中・選択範囲・`#`・音符の途中のキー・`staff` のグループ化を、手で確かめるための一覧。

**読み方**: `‸` はカーソル、`«…»` は選択範囲、`\n` は改行、`\|` は小節線。「打つ前」の状態でキーを押すと「打った後」になる。

**この表は実動作と照合している**: T・S・W の行は `npm test`（`test/typingCases.test.ts`）が 1 行ずつ打鍵を再現して確かめる。規則の番号は `src/smartTypingCore.ts` の先頭の一覧。Q の行は `LilySharp.Tests/PitchSpellingTests.cs` が確かめる。**機械が見られないのは 7 章の操作感だけ。**

## 1. 和音の括弧の中のキー（規則 33）

## 7. 操作感（実際のキーボードでだけ確かめられるもの）

- [ ] 2・3・5 章で、一瞬のちらつきが気にならない
- [ ] 長い曲（1000 小節程度）でも打鍵が遅れない
- [ ] JIS と US の両方の配列で `(`・`[`・`<`・`#` が動く
- [ ] 補完の一覧が開いている間に `c#` と打っても崩れない
- [ ] `f` `#` `4` と続けて速く打っても `fis4` になる
- [ ] 5 章をマウスのドラッグと Shift+↓ の両方で選択して、一覧の先頭が `grandStaff` になる
- [ ] 5 章の後、Ctrl+Z 1 回で元に戻る
- [ ] 何も選ばずに Ctrl+Space を押すと、今までの一覧が出る
- [ ] 2 章の後、その行より下の行の字下げが変わらない。`c4` の末尾で `(` を打って `)` が次の行へ行くときも同じ
- [ ] `c‸4` で `<` を打つと、カーソルが `>` の前に来る（実機でだけずれたことがある。隔離した VS Code で確認済み）
