## ⚠️ 起票の前提は実装前に倒れた

引継ぎ ⒟‴ は「**溢れは system を足すほど単調なので落ちる候補は全部 MaxValue ＝出力同一のはず**」と
書いていた。**LP の `prepend_system` の算術がそれを支持していない**:

```
rod_height_ -= first_line_.full_height ();
rod_height_ += first_line_.tallness_;
rod_height_ += line.full_height ();
```

出ていく先頭 system は **全高 → tallness** に払い替え、入ってくる先頭は**全高**を払う。
この 3 項に符号は無い。しかも `calc_force` が引く `min_whitespace_at_top_of_page (first_line_)` も
**先頭 system が変わるたびに変わる**。⇒ **頁は上へ育っても縮みうる。**
LP 自身のコメント（`:343-346`）も「**この if は少し読みにくい**」と heuristic として書いている。

⇒ **⒟‴ は「証明の付いた出力同一のリファクタ」ではなく、LP のアルゴリズムの移植**である。
§5.1 の 3 点証明は**結果**として使えるが、**構成**にはできない（§5.2「byte 不変は結果ならよいが
構成にしてはいけない」）。

### ★ falsifier と、外れたときに次にやること（フォーク）

**動いた本が 1 冊でも出たら、原因は 2 つのどちらかで、区別できる**:

- **⒜ tiebreak**: DP の更新は `totalPenalty < dp[curIdx]`（**厳密**）なので、**同点は先に来た i が勝つ**。
  走査の向きを変えた時点で、勝つ i が「最小の i」から「**最大の i**」へ移った
  （LP `:386` の `demerits < cur.demerits_` も同じ向き＝LP に寄る側）。
- **⒝ 早期打ち切りが溢れていない候補を落とした**（上の非単調性が現実に効いた）。

**分ける手順は 1 回**: **走査は降順のまま `break` を `continue` に替えて**同じ本を回す。
- **まだ動く → ⒜**（＝この移植は tiebreak を LP に合わせた。絵が動くので**承認ゲート**）
- **動かなくなる → ⒝**（＝非単調が実在。**LP の heuristic そのもの**なので、
  移植としては正しいが「LP と同じ絵になるか」を LP 実測で確かめてから）

⚠️ **どちらでも「退行」ではない**——⒜ も ⒝ も LP の字面に寄る向きの変化。
判断は「LP がその本で何を出すか」で、**Lily# の旧出力は基準ではない**。
